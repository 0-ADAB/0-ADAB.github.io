# 内容模型

> 本站的基本单位不是"一篇文章"，而是**实体 + 维度标签 + 关系**；
> 实体不是按栏目堆放，而是按**离结论有多远**分层。

## 一、为什么分层，而不是分栏目

按栏目组织（脑区一栏、方法一栏、数据类型一栏）会把同一个对象拆散：

- 「海马」既是**结构**，也处在某个**尺度**上，还参与**记忆**这个现象，又能被多种**模态**观测；
- 「时频分析」既是**方法**，又只适用于特定**模态**与**时间尺度**，且只能产出特定类型的**证据**；
- 「fMRI 激活差异」既是**数据**，也是一种**证据**，其可支持的**推断**有明确边界。

所以本站用两个正交维度定位任何一页：

```text
它在哪一层（离结论多远）  ×  它是什么类型的实体
```

## 二、四层结构

| 层 | 回答的问题 | 包含目录 | 变化速度 |
| --- | --- | --- | --- |
| **L0 导航层** | 我怎么进入、怎么跳转 | `00-导航/`、`09-关于/` | 稳定 |
| **L1 世界层** | 脑科学在研究**什么** | `01-尺度/`、`03-现象/`、`04-结构/` | 最稳定 |
| **L2 观测层** | 用**什么**看见它 | `02-模态/`、`05-方法/`、`07-资源/` | 稳定，工具类可动 |
| **L3 证据层** | 看见了能**说明什么** | `06-证据/`、`08-设计/`、`10-结论/` | 部分每周可动 |

依赖是单向的：**上层结论必须能回溯到下层观测**，下层不依赖上层。

```text
L1 世界层 ──被观测──▶ L2 观测层 ──产出数据、经推断──▶ L3 证据层
                                                       │
                                        L0 导航层 ◀────┘（入口与视图）
```

> L0 与其余三层不是并列关系：导航层不承载内容，只提供入口。

## 三、十类实体

| 类型 | 标签 | 目录 | 所属层 | 回答的问题 |
| --- | --- | --- | --- | --- |
| 尺度 | `类型/尺度` | `01-尺度/` | L1 | 在哪个空间/时间层级上观察 |
| 模态 | `类型/模态` | `02-模态/` | L2 | 用什么物理量测量，测得准不准 |
| 现象 | `类型/现象` | `03-现象/` | L1 | 对应什么功能、行为或疾病 |
| 结构 | `类型/结构` | `04-结构/` | L1 | 发生在哪里 |
| 方法 | `类型/方法` | `05-方法/` | L2 | 怎么算、能得出什么 |
| 证据 | `类型/证据` | `06-证据/` | L3 | 某类结果能支持什么推断 |
| **结论** | `类型/结论` | `10-结论/` | L3 | **目前可以较有把握地说什么** |
| 资源 | `类型/资源` | `07-资源/` | L2 | 用什么工具、去哪里学 |
| 设计 | `类型/设计` | `08-设计/` | L3 | 从问题到推断的完整路径 |
| 导航 | `类型/导航` | `00-导航/`、`09-关于/`、各 `index` | L0 | 怎么用这个站 |

**证据 ≠ 结论**，这是站内最容易混淆的一对：

- **证据页**讲某类数据在原理上能支持什么推断、在什么条件下失效 —— 是**能力**问题；
- **结论页**讲某个具体说法目前被检验到什么程度 —— 是**状态**问题。

十类实体之间用**双向链接**互相指向。任何一页都应能被至少三条不同路径找到。

## 四、frontmatter 契约

所有公开页面统一使用以下字段，**只允许这五个键**，以保证同步与渲染一致：

```yaml
---
publish: true              # 唯一发布开关
title: 页面标题
tags:                      # 1 个类型标签 + 1 个层标签 + 若干维度标签
  - 类型/方法
  - 层/观测
  - 方法/时频
  - 模态/电生理
  - 尺度/时间/毫秒
description: 一句话说明这页解决什么问题
aliases:                   # 旧链接、英文名、常见别名
  - 别名
---
```

## 五、标签体系

标签是**跨维度的第二套导航**。命名规则：

```text
层/<层名>            必填且只填一个：导航 · 世界 · 观测 · 证据
类型/<类型名>        必填且只填一个，对应十类实体之一
尺度/空间/<层级>     可选，多个
尺度/时间/<层级>     可选，多个
模态/<模态名>        可选，多个
方法/<方法族>        可选，多个
证据/<证据类型>      可选，多个
现象/<现象名>        可选，多个
```

已有取值：

- `层/`：导航 · 世界 · 观测 · 证据
- `尺度/空间/`：分子 · 突触 · 神经元 · 回路 · 脑区 · 网络 · 全脑 · 群体
- `尺度/时间/`：毫秒 · 秒 · 分钟 · 小时 · 天 · 发育 · 老化
- `模态/`：电生理 · 血流代谢 · 结构扩散 · 调控 · 行为眼动 · 生理化学 · 分子遗传 · 多人
- `方法/`：预处理 · 统计 · 连接 · 表征 · 解码 · 建模 · 多模态
- `证据/`：结构 · 功能 · 动态 · 因果 · 计算 · 一致性 · 边界
- `现象/`：感知 · 运动 · 注意 · 记忆 · 语言 · 决策 · 情绪 · 社会 · 意识 · 发展 · 临床

> `层/` 标签回答"这页位于哪一层"，`类型/` 回答"它是什么"，维度标签回答"它和什么有关"。三者齐备，页面才能被完整检索到。

**新增取值前先检查是否已有同类标签**，避免同义标签分裂成两张网。

## 六、页面骨架

### 通用头部

每页正文开头是一句话定义（可带 🌱/🌿/🌳 成熟度标记），随后是「定位」表：

```markdown
# 页面标题

> 一句话定义。 🌿 扩充中

## 定位

| 坐标 | 取值 |
| --- | --- |
| 所属层 | L1 世界层 |
| 空间尺度 | … |
| 时间尺度 | … |
| 相关模态 | … |
| 相关现象 | … |
| 相关结构 | … |
| 主要方法 | … |
| 证据类型 | … |
```

### 各类型专有段落

- **尺度页**：定义 → 定位 → 在这个尺度上能观测什么 → 不可观测什么 → 典型测量手段 → 与相邻尺度的衔接 → 跨尺度推断的陷阱
- **模态页**：定义 → 定位 → 物理量与被测量的关系 → 分辨率与采样 → 实验范式 → 常见分析 → 优势 → 局限 → 与其他模态的互补 → 常见误用
- **现象页**：定义 → 定位 → 行为指标 → 计算层面的描述 → 候选神经机制 → 各尺度证据 → 各模态证据 → 争议与未解问题 → 常见过度解读
- **结构页**：定义 → 定位 → 解剖边界与划分标准 → 主要连接 → 参与的认知过程 → 可用观测手段 → 分析方法 → 物种差异 → 命名与图谱争议
- **方法页**：定义 → 定位 → 输入数据要求 → 原理 → 输出结果 → 关键参数 → 前提假设 → 适用与不适用 → 常见误用 → 实现工具 → 延伸学习
- **证据页**：定义 → 定位 → 来源数据 → 可支持的推断 → 不可支持的推断 → 强度分级 → 常见的越界解释 → 与其他证据类型的关系
- **结论页**：定义 → **证据状态**（🟢/🔵/🟡/⚪）→ 直接观测到什么 → 从观测到结论补了哪些假设 → 支持与反对的证据 → 适用范围 → 不能据此推出什么 → 争议与替代解释 → 关键论文与资源 → 最近核查
- **资源页**：用途分类 → 条目表（名称 / 类型 / 适用数据 / 适用任务 / 难度 / 官方地址 / 维护状态）→ 使用建议 → 收录标准
- **设计页**：以流程图或步骤表呈现从问题到结论的完整链路，每一步给出对应实体链接
- **导航页**：入口清单与其适用场景，不承载研究内容

### 通用尾部

```markdown
## 相关

- 上级：[[对应目录/index|目录名]]
- 同层：[[同层实体]]
- 跨层：[[其他层实体]]
- 下游：[[可继续前往的页面]]
```

## 七、命名与链接约定

### 1. 链接一律相对发布根 `forAccess/` 写

这是本站**最容易犯、又最难发现**的错误：

```markdown
✅ [[02-模态/模态比较]]          ← 相对发布根
❌ [[02-模态/模态比较]] ← 带发布根前缀
```

原因：Syncer 的内容根是 `forAccess/`（配置项 `vaultPath`），**发布后 `forAccess/` 内部就是站点根目录**。带前缀的链接在 Obsidian 里能正常跳转，看起来完全合法，但发布到站点后会全部失效。

> 排查办法：`node tools/检查链接.mjs`，它会按发布根解析并报出所有失效链接。

### 2. 要发布的页面必须放在 `forAccess/` 内

`publish: true` 只是第二道闸门。**放在库根目录下的笔记不会被扫描，即使写了 `publish: true` 也不会发布**——在 Obsidian 里它一切正常，在线上却是 404。

两层闸门缺一不可：

```text
文件位于 forAccess/  ✅ 且 frontmatter publish: true  ✅   →  发布
```

### 3. 指向首页必须写 `[[index|首页]]`

Quartz 的 wikilink 只按**文件名与路径**解析，**不解析 `aliases`**，写 `[[首页]]` 会指向一个不存在的文件。

### 4. 表格内的链接要转义竖线

写成 `[[目标\|显示名]]`，否则会把表格截断。

### 5. 代码块内不解析链接

` ```text ` / ` ```markdown ` 里的 `[[...]]` 会原样显示。需要可点的链路请用**表格或列表**承载，代码块只放纯文本结构。

### 6. 其余约定

- **文件名唯一**：链接按最短路径解析，实体页文件名全库唯一；目录首页统一叫 `index.md`。
- **一层目录**：实体页直接放在所属类型目录下，不按主题再分文件夹；层级靠标签体现。
- **URL 小写化**：`EEG-64.md` 的站点路径是 `/04-结构/eeg-64`，中文路径会被编码，属正常现象。
- **别名保外部链接**：改名或迁移时把旧名写进 `aliases`，它会生成跳转页，保住外部已引用的网址（但不会让 wikilink 可解析）。

## 八、引用与立场

本站收录的是：方法能测什么、不能测什么；证据支持何种推断、何时失效；从问题到方法的路径；以及经三重检验的结论。

写作时必须区分四种句式：

| 句式 | 含义 | 示例 |
| --- | --- | --- |
| 能力陈述 | 方法原理上能做什么 | "EEG 可记录毫秒级的头皮电位变化" |
| 证据陈述 | 已有研究提示什么 | "多项研究提示…（须标注为提示性结论）" |
| **结论陈述** | 经三重检验后可较有把握地说什么 | "本结论处于🔵较强证据，适用条件为…" |
| 推断边界 | 不能得出什么 | "该结果不能直接推断单神经元的放电模式" |

**禁止**把相关性写成因果性，**禁止**把软件输出直接等同于心理过程或脑机制，**禁止**把单篇论文的结论写成站内结论。

## 九、如何扩展

新增一个实体页的标准流程：

1. 判断它属于哪一类实体与哪一层，放进对应目录；
2. 复制 `Templates/实体页模板.md` 里对应的骨架；
3. 填满 frontmatter 五个字段：一个 `类型/` 标签、一个 `层/` 标签；
4. 按该类型的骨架写正文，**定位表必须填**；
5. 在**上级目录的 index 页**里加一行链接，否则页面无法被导航到；
6. 与至少三个其他实体建立双向链接（尽量跨层，不要只连同类）；
7. 检查「不适用 / 局限 / 边界」段落非空——没有边界的页面不算完成；
8. 运行 `node tools/检查链接.mjs`，确认「问题合计：0」。
