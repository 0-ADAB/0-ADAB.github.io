# 🔄 每周更新

> 站点的内容分两种速度：**骨架几十年不动，证据每月在动**。这一页说明两者各自怎么更新。

🌿 扩充中

## 定位

| 坐标 | 取值 |
| --- | --- |
| 所属层 | L0 导航层 |
| 回答什么 | 什么每周更新、什么不更新、谁来决定 |
| 不回答什么 | 不记录研究结论本身 |
| 面向读者 | 想了解内容时效性的读者、以及维护者 |
| 节奏 | 每周六一次 |

## 两条更新线

把内容按**变化速度**分开，是这套机制的核心。两者混在一起，要么骨架被热点冲垮，要么时效性永远追不上。

| | 稳定知识层 | 动态研究层 |
| --- | --- | --- |
| 包含 | 层级定义、模态能力、方法假设、证据类型、推断边界 | 结论页的证据等级、外部入口可达性、待补清单 |
| 变化速度 | 以年计 | 以周计 |
| 每周做什么 | 只在发现错误时修正 | 例行核查与增量更新 |
| 是否会因为新论文而改写 | 不会 | 会 |
| 判断依据 | 长期共识、教科书级稳定度 | 系统综述、元分析、多团队重复 |

> **一条铁律**：新发表的单篇研究只能让结论页**增加一条待查线索**，不能直接把某个说法升级成"稳固共识"。升级必须人工确认。

## 每周六做什么

按顺序执行，每一步都可回溯：

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1. 可达性核查 | 检查各页外链与官方入口是否还活着、是否换了域名 | 失效链接清单 |
| 2. 结构自检 | 运行 `node tools/检查链接.mjs`，确认 frontmatter、链接、必需段落、目录登记四项为零 | 自检结果 |
| 3. 增量发现 | 检索上周新增的系统综述、元分析、领域共识声明 | 候选文献清单 |
| 4. 归类 | 把候选按主题映射到已有页面，判断是"补充"还是"新线索" | 映射表 |
| 5. 等级复核 | 对照 [[10-结论/index\|证据分级]] 复核是否足以改变某条结论的状态 | 状态变更提案 |
| 6. 人工确认 | 逐条审定状态变更与新增表述 | 定稿 |
| 7. 记录 | 写入本页下方的变更记录 | 本周条目 |

## AI 负责什么、不负责什么

**可以做**（可自动化、可回滚）：

- 发现候选文献、抽取摘要与主题；
- 检查链接可达性、检测页面是否过期；
- 建议标签、建议跨页关联；
- 生成本周变更摘要；
- 指出"被反复引用却没有专属页"的缺口。

**不可以做**（必须人工判断）：

- 把某个说法升级为「稳固共识」；
- 判断一项证据是否跨方法一致；
- 决定删除或改写既有结论；
- 替读者下"这意味着什么"的结论。

> 理由：AI 擅长**收集与比对**，不擅长**承担判断责任**。本站的可信度来自后者。

## 读者如何判断一页有多新

- 页面顶部的成熟度标记（🌱 雏形 / 🌿 扩充中 / 🌳 稳定）表示**这一页自身写完了多少**，不表示内容正确性；
- 结论页额外带**证据状态**（稳固共识 / 较强证据 / 开放问题 / 研究线索），表示**这条结论被检验到什么程度**；
- 两者相互独立：一页可以写得很完整（🌳），但结论本身仍是「开放问题」。
